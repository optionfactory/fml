### version 9.0.0

#### Upgrading from 8.x

The breaking changes, each detailed in its area below:

- ful no longer depends on bootstrap in any form (css, js, icon font): every style ships in `dist/ful.css`, themed through `--ful-*` custom properties. Pages that relied on bootstrap classes in the rendered markup, on `bootstrap.bundle.min.js` for the filter menus, or on the icon font must drop them; `ful-table`/`ful-pagination` icon config keys take icon names (`'search'`, `'chevron-left'`, `'chevron-right'`, `'arrow-clockwise'`) instead of icon-font class names
- the `--ful-inputs-*` theme variables are renamed `--ful-controls-*`, joined by `--ful-controls-height`
- the structural hooks are style-only tags (`ful-control-group`, `ful-affix`, `ful-control`, `ful-badge`, `ful-choice`, `ful-table-wrapper`, `ful-pagination-bar`, `ful-tablist`, `ful-accordion-group`, `ful-steps`, `ful-toast`, `ful-note`) and the chrome anchors on the rendered structure instead of the host tags: custom css written against `div.input-group`, `span.input-group-text`, `.form-label`, `.badges`, `.pagination`, `.page-item`, `.page-link`, `.table`, `.alert` or `.ful-select-input-container` must move to the new hooks
- `ful-spinner` is a style-only tag: the `Spinner` export and the `.ful-spinner-wrapper`/`.ful-spinner-icon` hooks are gone, a self-registering page drops its `defineElement('ful-spinner', …)` line, and `role="status"` is the author's to carry
- the positional slots of every field are `before` and `after` only, rendered inside a `ful-affix`; `ibefore`/`iafter` and the raw unthemed passthroughs are gone, so content once slotted raw now carries the addon styling
- the `disabled`, `readonly`, `required` and `value` claims stay live after the render, observed on the `Field` base; writing properties before the render is not supported, an attribute written between upgrade and render lands in the observed snapshot
- `ful-form` submits one exchange at a time: a submit while one is in flight is dropped before the values are extracted
- while a `ful-form` submits it carries `aria-busy`, and the submit and reset buttons it holds off carry `aria-disabled="true"` rather than the `disabled` property, so they keep the focus: page css selecting `:disabled` on those buttons selects `[aria-disabled="true"]` instead
- `ful-select.entry` answers `{ key, label, metadata }` entries instead of the `[key, [label, ...metadata]]` tuples exposed since ful 4.x
- the `csvm` attribute mapper is gone and `ful-select` declares `value:csv`: the value attribute is a comma separated list of keys whether or not the select is `multiple`. Nothing changes for a multiple select. A single select's attribute is now split and trimmed, so a key carrying a comma or padding (`value="a,b"`, `value=" it "`) must be assigned through the property, which does not go through the mapper. An element of your own declaring `value:csvm` moves to `csv` or to a mapper of its own through `static mappers`
- localization is one flat translations overlay: the plugin takes `new ful.Plugin({ language, translations })`, `ftl.Localization` is a plain template module (`#l10n:t()`, `#l10n:date()`, `#l10n:number()`, `#l10n:bytes()`), and the `l10n` static of `ParsedElement` subclasses is gone
- ftl: `data-tpl-text` and `data-tpl-html` are gone (`>{{ x }}<` and `>{{{ x }}}<` replace them), and only `text/html` scripts are parsed as slot markup: any other script type (modules, the `text/markdown` the wiki once suggested) slots as the plain node it is
- httpc: an error response whose body violates the `failures+json`/`problem+json` contract, does not decode, or is unreadable is a `GENERIC_PROBLEM` carrying the served status (it used to be `"undefined failures"`, a non-array `problems`, or a `CONNECTION_PROBLEM` with status 0); `Base64.decode` and `Hex.decode` reject invalid input instead of returning garbage; the csrf interceptor sends the token to the page origin only
- elements built on `ftl`: `render(c)` receives `{ slots }` alone and the base applies the declared attributes onto the properties as soon as it returns, in declaration order, so a render that read `c.observed` reads what it needs through `declared(name)` instead; `reflect(fn)` is gone and `reflectTo(name, value)` is the only way back to an observed attribute, marshalling through the mapper the attribute was declared with; an attribute name a subclass re-declares takes the subclass's position in that order, which is how a field states that its `value` lands after the attributes its value setter reads
- custom fields implement `_build(conf)` and return their pieces: `render`, `_adopt`, `_wireLabel` and `_wireA11y` belong to `Field` and are gone from the authoring surface, and `skipObservedSetup` with them. All three claims read the host attribute, announce on the element named by the `announces` piece, and a field with no usable native `readOnly` names a `freeze` piece whose gestures the base refuses. A field's change detail always carries its own `value`, and an empty field reports `null` rather than `undefined`
- `registry.upgrades`, a live `Map` iterator, is replaced by `pending()`, `whenUpgraded(el)` and `settle(accept)`
- one evaluation scope: `Template.withContext`, `withContextFrom`, `withModules` and `withData` collapse into `withEvaluator(evaluator)`, `Registry.context()` becomes `evaluator()`, and `Template.evaluate(expression, mode, ...data)` becomes `evaluateExpression(expression, ...data)` or `evaluateTemplated(text, ...data)`
- httpc tells a failed connection from a failed call: `CONNECTION_PROBLEM` now means the transport refused to deliver, a throw from the chain's own code (an interceptor bug, most often) arrives as `UNEXPECTED_PROBLEM` carrying the original as its `cause`, and `exchange()` rejects with an `HttpClientError` where it used to let the platform's raw `TypeError` through. `HttpRequestBuilder.param` overrides a key already set instead of appending to it, so a multi valued parameter is passed in one call
- `Timing.debounce(ms, fn, { immediate })` and `Timing.throttle(ms, fn, { leading, trailing })` take object options; the six `DEBOUNCE_*` and `THROTTLE_*` constants are gone, `{ leading: false }` and `{ trailing: false }` replacing the two throttle flags
- the plugin's overlay publishes `l10n` and `locale` only; `language`, which carried the primary subtag, is gone and `locale` carries the full tag
- `ful-pagination.update({ current, total })` replaces the positional `update(current, total)`, and the page being shown is marked `aria-current="page"` and stays enabled where it used to be disabled
- `ful-table` emits `page:requested` and `sort:requested`, joining the colon-namespaced request family; `page-requested` and `sort-requested` are gone
- `ful-select`'s change detail carries the keys as `value` with the labeled selection beside it as `entry`; a `preload` select paints its label, combobox and error region at once instead of holding its upgrade on the prefetch; `ful-dropdown` names its own listbox and announces its active option through an `activechange` event, and `aria-selected` marks the options that are picked rather than the one highlighted
- the `table.initial` message renders through `{{ }}` like every other built-in string: a consumer overriding it with markup now gets that markup as text
- a render failure carries one frame per nesting level instead of two, each naming its node rather than serializing it, so a page matching on `RenderError` message text reads `Error evaluating data-tpl-each="rows" in \`<ul>\`` where it read `Error rendering template` followed by the whole template
- the package declares `sideEffects: false`: bundler consumers importing through the root entry drop the unused parts of the bundle, and the `window.ftl`/`window.httpc`/`window.ful` assignments of the module entry may be tree-shaken away for them. Script-tag and CDN users of `dist/fml.mjs` are unaffected, `import * as fml` keeps the namespaces explicit

#### ftl: templates, expressions and the registry

- [REF] a class's `static config`, the constants its templates read as `config.*`, is read with the rest of its declaration when the registry is configured and travels in its `BITS`. The base used to loop over a one-element list of static names and look the value up on `this.constructor` every time a template was asked for, which had ftl reaching for a name only ful uses, once per render rather than once per class. A page overriding the constants replaces the static before `configure()`, like every other definition-time choice (`ful.Tooltip.config = { icon: 'my-icon' }` ahead of the plugin's configure); a replacement made afterwards is not picked up, where mutating the object in place still is
- [ENH] asking an element for an attribute its class never declared says so, with `Select declares no attribute 'my-endpoint': declare it in static observed or static attributes, or read it with getAttribute`, where `unmarshal` used to die on the missing mapper with `Cannot read properties of undefined`. The message names the wall it is: content an element does not own, a custom loader's own configuration on a `ful-select` host being the case that matters, is read with `getAttribute` like any other markup, and `declared(name)` answers for the declared vocabulary alone
- [BRK] `reflectTo(name, value)` is the one place a property is projected back onto its observed attribute, and `reflect(fn)` is gone. Sixteen setters re-opened the guard and re-encoded the mapper by hand, using `toggleAttribute` for the presence attributes, `Attributes.set` for the numbers, and a `setAttribute` carrying the browser's normalization of `accept` rather than the marshalled value, while two call sites used the method that already existed. A setter now hands over its value and never knows how its type serializes
- [ENH] a reflection that would write what the attribute already carries writes nothing, so reflecting a value an attribute change just delivered ends there instead of travelling back through the observer, and the mute is the attribute being written rather than the whole element. Deleting `reflect(fn)` is what closes the hazard the instance-wide mute carried: an arbitrary block ran under it, so any observed attribute a component legitimately changed while inside was silently dropped. Two blocks were not reflections at all: `ful-sorter` wrote `aria-sort` onto its ancestor `th`, which the guard never covered anyway, and `ful-pagination` re-rendered its whole bar inside it
- [BRK] `render(c)` receives the slots alone and the base applies the declared state onto the properties as soon as it returns, in the order the registry composed the declarations. Every element used to be handed an `observed` bag, and every one of them did the same thing with it: assign each value to its own property. `Field` had the generic loop; `ful-tabs`, `ful-sort-button`, `ful-pagination`, `ful-wizard` and `ful-accordion` hand-rolled a subset of it, and `ful-checkbox` and `ful-radio-group` destructured a bag they never read. A render needing a declared value while it builds reads it through `declared(name)`. The defaults those call sites carried moved into the setters that should always have had them, so an absent `total` or `current` on `ful-pagination` is zero rather than the string `"null"` in the dom
- [NEW] `static attributes` is the configuration tier, beside `static observed`: read once through its mapper when the upgrade starts and answered unchanged for the element's life, where an observed attribute stays live, forwarding to its property. The registry already composed the list and gave it a mapper, but nothing read it, so configuration was raw `getAttribute` at render (or at every use) with nothing in the class saying which. `ful-tooltip`, `ful-dialog`, `ful-drawer`, `ful-toasts`, `ful-table`, `ful-sorter`, `ful-select`, `ful-dropdown`, `ful-radio-group` and `ful-checkbox` declare theirs, and `declared(name)` reads either tier
- [BRK] a name a subclass re-declares takes the subclass's position in the composed order, which is what lets a field state that its value lands after the attributes its value setter reads: `ful-input-file` re-declares `value` after its constraints, since assigning one validates the selection against them. It used to work because `Field` special-cased `value` last, a rule the base could not state without knowing ful's vocabulary
- [BRK] the `csvm` mapper is gone, and `ful-select` reads its `value` as a plain `csv`. It was a general-purpose extension point built for one attribute: it hardcoded the literal string `multiple` in ftl's mapper table, which is a ful convention sitting in the layer that knows nothing about ful, and its `marshal` half was never reached from any element, since no field reflects `value` (the attribute is the initial value, as on a native input). Both of that marshal's branches computed the same string in any case, `String(array)` being `array.join(',')`. The select's `value` setter already normalized a scalar, a list or `null` into keys and its getter already answered a scalar for a single select, so reading every value as a list changes nothing a multiple select does and costs a single select the ability to carry a comma or surrounding space in a key given through markup. The declaration comment claiming `multiple` had to be declared before `value` described a constraint that did not exist: the mapper read the markup attribute and the element read `declared('multiple')` in its build, both before any property was applied
- [REF] `Registry.declarationsOf(klass)` is the one composition of a class's attribute declarations. The chain was walked in three places, the registry, the manifest generator and the metadata parity test, with two different stop conditions and two of them reading only `observed`, so the IDE metadata documented none of the configuration tier: `ful-tooltip`, `ful-dialog`, `ful-drawer`, `ful-toasts`, `ful-table`, `ful-sorter` and `ful-dropdown` each documented zero attributes while carrying author-facing ones. The manifest now describes 106 attributes where it described 90
- [BRK] a render failure carries one frame per nesting level instead of two, and each frame names its node rather than serializing it: `RenderError`'s message reads `Error evaluating data-tpl-each="rows" in \`<ul>\``, naming the directive, its expression and the node's open tag, where it used to read `Error rendering template` followed by the whole template's markup. The chain is the path from the outermost nesting down to the offending expression, which is what the two-frames-per-level shape buried; the render-level wrap now passes a framed failure through instead of adding a second frame for the fragment containing it
- [ENH] the chain spends a budget: `RenderError.FRAMES` frames are kept, the innermost being the specific ones, and a deeper nesting drops the outer context and sets `truncated` so a report can say so. The node's markup is no longer cloned into every frame either: `RenderError.html` serializes it when asked and `RenderError.node` is the live node, where the constructor used to deep-clone twice per frame on the failure path
- [BRK] the evaluation scope, the modules plus the data stack, is one value instead of a pair threaded by hand: `ExpressionEvaluator` is that value, a `Template` is a fragment plus one, and a `Registry` holds one it replaces whenever a module or an overlay is defined. `Template.withContext`, `withContextFrom`, `withModules` and `withData` collapse into a single `withEvaluator(evaluator)`, the one way to rebind a compiled template to a registry's scope, and `Registry.context()` is gone in favour of `evaluator()`. The nine command handlers and the render loop take the scope instead of the positional pair, and `Template.fromHtml(html, modules, ...data)` keeps its signature
- [BRK] the templated-versus-expression mode stops travelling as an optional middle argument: `Template.evaluate(expression, mode, ...data)` becomes `evaluateExpression(expression, ...data)` and `evaluateTemplated(text, ...data)`, and `ExpressionEvaluator.evaluate(expression, mode)` is replaced by the same pair, which it already carried. The mode symbol stays inside `Expressions`, where the parser needs it for its start rule
- [BUG] `Localization.of()` resolves through the registry's own scope instead of a private copy of the lookup: the copy skipped function overlays, which the evaluator honours, so a page whose translations arrived on one answered a different message imperatively than through `#l10n:t()` in a template. The lookup now exists once, as `ExpressionEvaluator.resolve(name)`, and the facade still reads it per call so a module-scope `Localization.of()` bound before `configure()` keeps working
- [ENH] an element resolves through the registry that defined it, not through whichever one a module imported: the definition carries its registry in `BITS`, `ParsedElement` gained `component(name)` and `_registry`, and `template()` reads its own registry's context. `ful-form`, `ful-select` and `ful-table` no longer import the singleton, and the three loader factories resolve `http-client`, the request and response mappers and the `loader` component through the element they are handed, so a `new Registry()` is a working host for the elements it defines
- [BRK] `registry.upgrades`, a live `Map` iterator, is replaced by three named methods: `pending()` answers a snapshot of the elements still queued, `whenUpgraded(el)` the pending upgrade of one of them, and `settle(accept)` the rejecting barrier `Rendering` is now a three-line facade over. The queue keeps one entry per element holding both signals, the never-rejecting readiness one and the rejecting upgrade, where two maps were kept in lockstep by hand behind two fixed-point loops
- [BUG] a render that threw no longer opens the attribute-to-property forward: `#parsed` is set after a successful render, so a later attribute write on a half-rendered element stops reaching setters that dereference pieces the failed render never adopted, where it used to raise a second, unrelated TypeError over the reported failure
- [ENH] `ParsedElement.rendered` answers whether the render completed, the moment the properties went live: `ful-tabs`, `ful-wizard` and `ful-toasts` each kept a private flag for that fact and now read the base's
- [BRK] `data-tpl-text` and `data-tpl-html` are gone, text and html land through the interpolations alone: the interpolation is a child text node instead of replacing every child, which nothing relied on. `{{{ }}}` accepts any value the attribute form accepted (numbers and `toString`-ables stringified, `null` and `undefined` rendering nothing) and `{{{{ }}}}` with a non-Node reports `Expected a Node`
- [BRK] only `text/html` scripts are parsed as slot markup; a page using another type as a markup container moves to `text/html`, and no script source is ever innerHTML-ed again
- [NEW] `data-tpl-stat` names an iteration stat beside `data-tpl-each`'s item: `{ index, count, size, first, last, even, odd }`, grouped under the declared name so it can never collide with data (an item property sharing the name wins). The stat observes without changing consumption: the size is read where the collection already knows it, and an iterator or generator is never consumed to learn it, its `size` and `last` reading null
- [ENH] `data-tpl-each` iterates keyed collections as `{ key, value }` entries: a `Map` in its own order, a plain object in `Object.entries` order (`<li data-tpl-each="languages">{{ key }}: {{ value }}</li>`); every other iterable iterates as itself, and a non-plain non-iterable still fails loudly
- [ENH] `registry.ready()` is the awaitable form of `ftl:ready`: the same promise for every caller, resolving right after the event and immediately when that moment already passed. Importing the registry after the document's DOMContentLoaded no longer strands the waiters (in the window before load included, the wait racing the two events rather than guessing from `readyState`), and a last-in-document element no longer strands its upgrade on a listener that would never fire
- [BUG] expressions: identifiers sharing a keyword's prefix (`nullable`, `nullish`, `falseFlag`, `truex`) parse again, the identifier rule taking the whole word and classifying the exact keywords after it; a call on a missing value reports `Method missing` (by name where the grammar knows it, a bare `boom()` included) instead of crashing while building its own message; a template string is a valid dict key, evaluated like any other, where `{`{k}`: 1}` used to collapse into a literal `"undefined"` key
- [BUG] a lone `{` in a templated text node renders as itself: the parser's negative lookahead leaked into the joined parts, so a text carrying interpolations plus a single brace (`cost {{x}} is {high}`) rendered a stray comma
- [BUG] fireAsync: a pipeline or delegate configured wrong still throws its configuration error to the caller, but the outcomes of the listeners it already dispatched are owned instead of surfacing as unhandled rejections the page's error reporter would post

#### httpc, client-errors and storage

- [NEW] httpc exports every type its own signatures hand back: `HttpClientBuilder` (what `builder()` answers), `HttpRequestBuilder` (what all seven verbs answer), `HttpInterceptorChain` (what an interceptor is handed) and `HttpMultipartRequestCustomizer` (what a `multipart` callback is handed). They were reachable and unnameable, emitted into `httpc.d.mts` as non-exported `declare class`, so a consumer could write the call but not annotate the function it lives in, nor type the `chain` parameter of an interceptor of their own. The two built-in interceptors stay unexported: they are page policy the builder installs, not a type anything hands back
- [BRK] a connection problem is the connection failing, and nothing else: `HttpCall` labels its own rejected `fetch` as `CONNECTION_PROBLEM` below the chain, so a throw from the chain's own code, most often a bug in a consumer's interceptor, reaches the caller as `UNEXPECTED_PROBLEM` carrying the original as its `cause`. `fetch()` still answers a `Failure` whatever was thrown, so a caller reading `problems` never has to test the shape first; it is the label that stopped sending readers to look at the network for a `TypeError`. The reporter walks the cause chain, so the real stack now arrives in the report where it used to flatten to `unknown failure`
- [BRK] `exchange()` answers the same failure the request builders do when the transport refuses: the wrap moved below it, so a network failure is an `HttpClientError` there too rather than the platform's raw `TypeError`. The same fact reads the same way whichever call was made
- [REF] `HttpClientError.problem(type, reason)` mints the problems the client makes itself; the object was spelled out at four sites
- [BUG] client-errors reports the cause chain: it read `message` alone, and neither a message nor a stack carries `cause`, so every framed failure in the library arrived naming where it surfaced and never what caused it. The report now walks the chain to a bounded depth, joining the frames with `Caused by:` lines, stopping on a cycle, and noting when a chain dropped its outer frames
- [BRK] the request url is built instead of spliced: a second `?` no longer truncates the query and a `#` no longer swallows the parameters into the fragment where the server never sees them (the fragment is split off and reattached after the parameters, the query splits at its first `?` only); `param` skips nullish entries among real values in any position, like the plural forms always did
- [BRK] an error response reports faithfully whatever went wrong with its body as a `GENERIC_PROBLEM` carrying the served status: not decoding as json (a proxy's html error page carrying the wrong content type, a truncated response), decoding to json that violates the `failures+json`/`problem+json` contract, or unreadable altogether. Previously a served response was mislabeled as a network failure with status 0 and the status hidden behind a json parse error
- [BRK] `Base64.decode` and `Hex.decode` reject invalid input (characters outside the dialect, misplaced or overlong padding, impossible lengths, non-hex characters) instead of returning plausible-looking garbage
- [BRK] the csrf interceptor carries the token to the page origin only, so a cross-origin request no longer ships the session token to a third party; it reads the meta pair at request time, so metas landed after the client was built are honored without a rebuild
- [BUG] `HttpClient.exchange()` normalizes its options before the chain sees them, every interceptor receiving a `RequestInit` with a real `Headers` however bare the call. A bare `client.exchange(uri)` under a `CsrfTokenInterceptor` (the ful plugin registers one by default) used to crash on the missing headers field
- [ENH] `fetchJson()` yields `null` on a 204 instead of failing to decode the body the status declares absent
- [BUG] client-errors sends the csrf header only when the meta pair is complete (a half-configured page used to send a literal `"undefined"` token on every report), and its missing-attribute complaint is logged once per page, not once per captured failure
- [BUG] storage: an unreachable backing (blocked cookies, and the embedded or private contexts where the accessor itself throws) reads as a miss and removes as a no-op instead of failing the caller, so a revisioned `ful-select` still loads its options from the network there; writes keep reporting to their caller

#### Localization

- [BRK] the plugin's overlay publishes two names, not three: `l10n`, the messages a template resolves through `#l10n:t()`, and `locale`, the full tag every formatter needs. The `language` key carried the primary subtag, which exists to pick which built-in bundle is layered under a consumer's strings and is read by nothing once that is done: a bare, generic name occupying the scope of every template on the page for no reader. A page that wants it takes it from `locale`
- [BRK] localization is a single flat translations map instead of per-class dictionaries: `ftl.Localization` is a plain template module (`#l10n:t('pagination.showing', …)` with named `{placeholders}`, `{ one, other }` plural leaves selected through `Intl.PluralRules` over a numeric `{count}`, and `#l10n:date()`/`#l10n:number()`/`#l10n:bytes()` honoring the page locale), resolvable from any template or imperatively through `Localization.of()`. The messages live in per-language files under `src/ful/l10n/`, kept at parity across languages by a dedicated test; the `l10n` static of `ParsedElement` subclasses is gone
- [BRK] the ful plugin takes `new ful.Plugin({ language, translations })`: the language is fixed per page (a full BCP-47 tag or a primary subtag, defaulting to the browser's) and the fallback chain is baked once at configure into one `l10n` overlay; `translations` is a flat active-language map applied over the built-ins, rewording them or adding keys of your own, and a remote set is an awaited `fetch().json()` handed over before `configure()`
- [ENH] `ful-local-date` and `ful-instant` resolve their locale from their `locale` attribute, the page's locale, then the platform default; file size warnings carry locale-formatted digits (`1,5MiB` in Italian) through `#l10n:bytes()`, replacing the bespoke byte formatter
- [ENH] `bytes` gained the GiB tier, and a size exactly on a threshold takes the larger unit (1024 is `1KiB`, where it read `1024B`)

#### ful: forms and fields

- [BUG] a submitting form announces itself. It carries `aria-busy` while the pipeline runs, the way `ful-table` and an async section already declare themselves busy, and every `ful-spinner` it reveals is given `role="status"` and the localized `spinner.loading` label unless the author wrote text of their own. Making `ful-spinner` style-only in this release moved the role and the label to the author, and no form had been updated to carry them, so the one wait in the library with a network round trip behind it was the one wait announced to nobody. The label is appended after the reveal, since a live region filled while hidden is announced unreliably, and removed on release rather than left in a hidden region
- [BRK] the buttons a submitting form holds off are marked `aria-disabled="true"` and refused through a capturing click handler, where they used to have the `disabled` property set. The submitter is almost always the focused element when a submit starts, and disabling what holds the focus drops it to `<body>`: the user lost their place in the document mid transaction, and with nothing announced either, the whole exchange passed in silence. Held off this way a button keeps its focus and its name, and `.ful-button` already dimmed both spellings; a rule in `form.css` dims an unstyled one. Page css keyed on `button[type=submit]:disabled` inside a `ful-form` matches `[aria-disabled="true"]` instead. Nothing about double submits changes: `submit()` has always dropped a call made while one is in flight, and the button state was affordance
- [BUG] `Bindings.extractFrom` submits the name of the button that submitted the form and of no other, which is the platform's own rule. It used to fall out of every button having been disabled by the spinner before the values were read, so a second submit button's `name`/`value` would have joined the payload the moment the disabling stopped: the affordance was quietly load-bearing for what travelled

- [BUG] a readonly field stays in the accessibility tree: `readonly` used to set `inert` on the container of every field with no usable native `readOnly`, being `ful-checkbox`, `ful-radio-group`, `ful-input-file`, the compare filters and `ful-filter-boolean`, which removes the whole subtree from the accessibility tree, so a readonly field was fully visible on screen and its value could not be read at all. The claim now refuses the gesture instead, through one capturing click handler the base installs on the frozen part: the platform's activation is cancelable, so a click neither toggles a checkbox, picks a radio, opens the file picker nor opens a filter's menu, while everything stays focusable and readable
- [BRK] the claims announce on the element whose role accepts them, which a field names through the `announces` piece: `aria-required` used to ride wherever the claims did, so `ful-radio-group` set it on its `<fieldset>`, a `group`, which accepts neither `aria-required` nor `aria-readonly` and dropped both. It now announces on the host, which carries the `radiogroup` role; `ful-filter-boolean`, whose control is a button, announces nowhere rather than emitting an attribute the role refuses
- [BRK] all three claims read the host attribute, as `disabled` already did: `readonly` used to read the frozen container's `inert` and `required` the control's `aria-required`, so each claim answered from its own projection. The setters have always reflected the attribute, so one read now answers whatever the field projects, including a field that projects nothing
- [BRK] a field's change detail always carries its own `value`, so `el.value === evt.detail.value` holds for every field; `Field._notifyChange(extras)` takes the extra keys a field wants to add beside it rather than a replacement value
- [BRK] an empty field reports `null`, never `undefined`: the three filters answered `undefined` for "no criteria" where every other field answered `null`. The extracted form values are unchanged, since `Bindings.providePath` already wrote `null` for both; only a direct read of a filter's `value` differs. `undefined` keeps its one meaning inside `Bindings`, where an unchecked native radio abstains so it cannot clobber a checked sibling sharing its name
- [BUG] `Bindings.providePath` refuses a `__proto__`, `prototype` or `constructor` segment instead of walking into it: a dotted field name reaching the prototype chain wrote on every object in the page, since `__proto__` passes the `typeof === 'object'` test the walk uses to decide whether to rebuild an intermediate. Field names are author markup, but one can be bound from data through `data-tpl-name` and `providePath` is public, so the segments are refused outright, before anything is written
- [ENH] `new ful.Plugin({ httpClient })` takes the client every ful component fetches through, registered as the `http-client` component. Where an unauthorized session goes is an application decision, so a page that does not want the built-in redirect to `/` hands over its own client; the default is unchanged
- [ENH] the select's dropdown is a popover anchored on its control group through css anchor positioning, `anchor-size()` stretching it to the group's width, like the filter menus and the tooltip's note: it renders in the top layer, above every stacking context, so it is no longer clipped inside overflow containers (cards, table wrappers, scrollable dialog bodies) nor covered by later siblings and sticky headers. The `popover` attribute stops being a selector hook: the dropdown opens and closes through `showPopover()`/`hidePopover()` as a manual popover, the combobox keeping the focus on its input and owning the lifecycle (typing, arrows, blur, Escape, Tab) as before
- [BRK] the positional slots of every field are the themed ones only: `before` and `after` render inside a `ful-affix` and replace `ibefore`/`iafter`, which are gone along with the raw unthemed passthroughs, a bootstrap-era escape hatch for hand-written input-group markup unused since the restyle
- [BRK] the `disabled`, `readonly` and `required` claims and the value stay live on every field, observed on the `Field` base and composed along the inheritance chain, so a post-upgrade `setAttribute` reaches the claim, the inner control and the form's extraction together. The value defaults to the string mapper, every field with its own vocabulary overriding it (`value:bool`, `value:csvm`, `value:json`); an attribute write arriving between upgrade and render lands in the observed snapshot and is applied by the render (a `ful-select` whose prefetch is in flight keeps a claim, or a `value`, made while it loaded), the properties going live only after the render
- [BRK] `ful-form` submits one exchange at a time: a submit while one is in flight is dropped before the values are even extracted, nothing fires and nothing travels, so a second Enter or a programmatic call racing the first cannot double the write; `spinner()` still nests for a caller's own wraps
- [ENH] `Field` is exported from the ful entry: the base of every form-associated field, carrying the validity protocol (`setCustomValidity` over the element internals and the `ful-field-error` live region), focus delegation, the label/aria chrome, Enter submission, the claim protocols and the reset protocol. A custom field extends it, owns its template and value semantics, and hands its rendered pieces over through `_adopt`/`_wireLabel` once its render queried them; a custom field's `form.reset()` no longer crashes on a missing value mapper, the base's inert pair absorbing the write
- [REF] `ful-input`, `ful-select`, `ful-checkbox`, `ful-radio-group` and `ful-filter-boolean` extend `Field`, where each protocol was a copy per element. No field overrides a claim accessor any more: which pieces it hands to `_adopt` is the whole of its strategy, `freeze` naming the element the readonly claim inerts for a field with no usable native `readOnly` (`ful-checkbox`, `ful-radio-group`, `ful-input-file`, `ful-filter-boolean`, the compare filters' control group), `claims` moving all three onto a wrapper the field disables as a whole (`ful-radio-group`'s fieldset, which also carries the requirement) and `also` naming further controls that mirror beside the first (a compare filter's second operand)
- [BRK] `Field._adopt`, `_wireLabel` and `_wireA11y` are gone from the authoring surface: a field no longer calls back into its base to wire itself. `_build` answers what it produced and the base does the rest, so those three are private to `Field` and cannot be called at the wrong moment. The pieces are `fragment` (mounted on the host), `control` (the focusable target that focus, the aria and by default the three claims reach), `error`, `label` (names the control and focuses it on click), `described` (moves the error's description off the control, onto the host where no single control can carry it), `claims` (moves the three claims onto a wrapper the field disables as a whole), `freeze` (the element the readonly claim inerts, for a field with no usable native `readOnly`) and `also` (further controls mirroring disabled and readOnly beside the first). A field extending another spreads the pieces its parent answered and overrides the keys it owns
- [BRK] `render` on a field belongs to `Field`: a concrete field implements `_build(conf)` instead, builds its dom there and hands its pieces to `_adopt`, and the base applies the declared state once it returns. `_build` may be async, as `ful-select`'s is while it awaits its prefetch, and a field that builds synchronously stays synchronous. The snapshot is assigned in declaration order with `value` last whatever its position, since every value setter reads the rest, so a field no longer re-lists its ancestors' attributes: the undocumented `skipObservedSetup` flag is gone with the two subclasses that passed it, and the dead `if (!this._input) return` guards go with it. `ful-input-local-date`, `ful-input-local-time` and `ful-input-instant` declare `['step', 'min', 'max']` so the order that matters is the declaration's, and their render overrides are gone. ftl gains nothing for this: the whole sequence lives on `Field`
- [BUG] `form.reset()` restores every field, not only `ful-input`: the declared `value` attribute routes back through each field's own mapper and value setter, so `ful-checkbox`, `ful-select`, `ful-radio-group`, `ful-input-file`, `ful-input-local-date`, `ful-input-instant` and every `ful-filter-*` reset through their own semantics. A file field resets to no selection, and a valueless filter also brings its operator and case sensitivity back to the defaults it rendered with
- [ENH] form error mapping: a field error pins on the most specific name its context reaches (deep contexts still catch onto the composite field owning the subtree, which receives the remaining path as `setCustomValidity`'s second argument to route the problem internally), and a context naming no field reads in the banner instead of vanishing
- [BUG] a `FIELD_ERROR` or `INVALID_FORMAT` problem carrying no `context` lands in the `ful-errors` banner instead of crashing the display: `Bindings.errors` used to call `.replace` on the null context, and the TypeError escaped the form's error handling as a rejected `submit()` with no field errors shown
- [BUG] Enter on a field submits through a submitter the form actually owns: `Field._requestSubmit` skips submit buttons associated with another form (`form=""` included, a pattern ful itself renders) instead of handing a foreign submitter to `requestSubmit()`, which throws per spec; Enter never submits from a file field, whose Enter opens the picker as a native file input's always did
- [BUG] overlapping names (`a` alongside `a.b`) no longer abort the extraction with a TypeError, the later, more specific name winning as the reverse order always did
- [BUG] a submit button that joined the form mid-spin keeps its authored state when the spinner restores (the saved ones restore as before)
- [BUG] a malformed mask is warned once and then ignored, instead of throwing on every keystroke
- [ENH] `ful-input` decodes its value to a number under `v-type="number"`, an explicit opt in like the select's `k-type`: blank stays null, a value that does not decode is kept as it is, the change detail and the form extraction carry the number, and an undeclared `type` defaults to `number` so the numeric widget rides along (a declared one wins)
- [BUG] `ful-radio-group` assigned an unknown key clears its selection, like a null assignment and like the select's unknown keys, instead of leaving the stale radio answering; its internal fieldset pins its own layout (`display: block`, full width), so a host page's global `fieldset` rules can no longer shrink the radio list into its content
- [BUG] a `ful-checkbox` with a long label keeps it beside the checkbox: the label fills the row and wraps its own text instead of being pushed under the checkbox, with the label's hit area covering the row
- [BUG] instants: a date-only iso value (`2024-03-15`) is read as local midnight wherever an instant is concerned, so a bound names the day it names in every timezone instead of the utc midnight that shifts west-of-utc users to the previous day; a value that does not parse (a datetime-local widget degraded to plain text on an older engine) reports no value instead of throwing a RangeError
- [BUG] `ful-local-date` and `ful-instant` render the `default` attribute's text for content that does not parse, like blank content, instead of failing their upgrade on an invalid date
- [ENH] validation errors satisfy WCAG 4.1.3 (status messages) by default: a `ful-field-error` is a polite live region and the `ful-errors` banner carries `role="alert"`, both announced without focus. A form with `scroll-on-error` keeps its focus management as the single announcement channel instead: the field errors' live region is turned `off` there, so the focused field's `aria-describedby` reads each error exactly once while the banner still announces on its own; the field's error text sizes a step under the label

#### ful-input-file

- [NEW] a `<template slot="items">` replaces the stock row of the item list, the way `ful-select` already takes one. The two fields both render a `ful-item-list` and only the select could reshape it, so a thumbnail preview, a per type icon or any richer row meant subclassing a field whose template was otherwise fine. The overlay is unchanged, `files` bound to the live `FileList`, so an authored item reads the whole `File` and `file.type.startsWith('image/')` evaluates like any other method call on data; the field still matches an item to its file through `data-tpl-data-name` and still treats the item's button as the remove control, so a custom row wires nothing. Thumbnails need an object URL, which no built-in module mints and nothing revokes: a short-lived form can register a one line module for it, a long-lived page wants a subclass that revokes what it created
- [REF] `InputFile.list(files)` builds the FileList every narrowing of a selection needs. The platform offers no way to make one but through a `DataTransfer`, so removing a chip, accepting a drop, dropping the unacceptable files, dropping the oversized ones and assigning a single file each rebuilt it by hand, with three more constructions for an empty one: eight sites, one helper
- [ENH] the file list entries are deletable chips (see ful-select below for the shared chip pattern), the file's size riding along muted; the default dropzone is themed like the rest of the library (dashed border, theme radius, hover ring, filled drag-over state; it was a `5px solid blue` placeholder), and the native `choose file` button is restyled as an affix-like leading control of the group. A slotted custom dropzone keeps rendering as plain user content, with a `dragover` attribute toggled on `ful-input-file` as the opt-in styling hook
- [ENH] `accept` honors the whole vocabulary: mime types with parameters ignored, and `image/*`-style families, not extensions alone; a drop carrying more than one file on a single-file field is rejected whole, as the native input's own drop is, and a dropped directory is ignored
- [ENH] drops and item removals report through `change` as a picker selection does; programmatic `files`/`value` assignments and the form's reset stay silent, like a native input's
- [ENH] the claims hold on the chrome: a disabled or readonly field accepts no drop, dismisses no removal and opens no picker (readonly freezes the whole control group, a file input having no native freeze)

#### ful-select

- [NEW] `SelectLoader.from(conf)` builds a loader from a plain configuration and reads no dom: `data` alone is the in-memory vocabulary, a `url` is fetched whole or per query under `mode: 'chunked'`. `create(el, conf)` is the same thing with the element's attributes parsed first, so a caller with its own configuration, or a test exercising the fetch discipline, no longer has to fake an element carrying the right attributes to get a loader, which is what the suite did
- [NEW] the loader's whole vocabulary is declared configuration: `src`, `method`, `mode`, `preload`, `revision`, `k-expr`, `l-expr`, `d-expr`, `m-expr` and `response-mapper` join `name`, `loader` and `k-type` in `static attributes`, read once at the upgrade through their mappers. They were raw attribute reads scattered through the loader factory and its response mapper, invisible to the manifest: the IDE metadata documented three of the select's attributes and now documents thirteen
- [BUG] `multiple` is observed, declared before `value` so the two cannot disagree. The `csvm` mapper reads the `multiple` attribute to decide whether a value parses as a list or a scalar, while the element froze its own copy at render: toggling `multiple` afterwards changed how `value` parsed and nothing else, for the life of the page. It is a property now, and the manifest documents it
- [BRK] one entry shape end to end: every loader method, being `prefetch`, `load`, `exact` and `update`, and every `response-mapper` component answers `{ key, label, metadata }` entries, the vocabulary `.entry`, the change detail and the items overlay already spoke. The positional `[key, label, ...metadata]` tuple survives only as the wire format servers send, which the default response mapper converts; a custom loader or a named `response-mapper` answers entries. `metadata` is one value, the `m-expr` expression's, where `.entry` used to answer the positional tail as an array: a loader with several things to say packs them into an object
- [BRK] the change detail carries the select's own `value`, the keys, with the labeled selection beside it as `entry`: `evt.detail.value` used to be the selection, the one field in the library whose detail was not its value. A listener reading the labels moves from `evt.detail.value` to `evt.detail.entry`
- [BRK] a preloading `ful-select` paints its label, combobox and error region at once instead of holding its whole upgrade on the prefetch: the vocabulary is the dropdown's concern, so a slow or failing endpoint degrades the options rather than the field, and the properties go live with the chrome. A `preload` select carrying a declared `value` may briefly show its keys before the labels resolve, as a non-preloading one already did; the loader shares one in-flight fetch, so a first open during the prefetch joins it rather than duplicating it
- [BRK] `ful-select.entry` answers `{ key, label, metadata }` entries, the vocabulary the change detail and the items overlay already speak, instead of the raw `[key, [label, ...metadata]]` tuples exposed since ful 4.x: one selection shape everywhere
- [ENH] it acts like a select: clicking anywhere on the field, the input included, toggles the dropdown; opening it highlights the current selection instead of always the first row; `Alt+ArrowDown` opens and `Alt+ArrowUp` closes; `Home`/`End` jump to the first/last option and `PageUp`/`PageDown` page through the list one visible page at a time; `Escape` aborts a pending search besides closing
- [ENH] a single select mirrors its label in the field at rest: the text is selected on focus so typing or a backspace replaces it whole, and closing the dropdown, blurring or escaping brings the label back. Opening the list from rest offers every option, the displayed label never used as a needle. The lone `ful-badge` of a single select is gone, and the inner input carries `autocomplete="off"`
- [ENH] the dropdown announces the highlighted option through `aria-activedescendant` on the combobox input, cleared as the dropdown hides; an empty dropdown says so with a localized, politely announced "No results" instead of the CSS-only icon, exposing no empty listbox; the highlight's smooth scrolling yields to `prefers-reduced-motion`
- [BUG] a failed open no longer leaves the combobox announcing an expanded, hidden list: every hide collapses the combobox, the load failure still reported as it always was
- [ENH] the chips of a `multiple` select are keyboard reachable: `ArrowLeft` at the start of the field hands the focus to the last chip, the arrows walk the chips and return to the field, `Enter`/`Space`/`Backspace`/`Delete` remove the focused chip, `Escape` goes back to the field. `ful-badge` is a neutral value chip (selected background, border and text colors) instead of the accent fill it borrowed from `--ful-active-bg`, which read as a primary action button; it tints on hover and focuses through its border
- [ENH] the item lists are deletable chips, shared with `ful-input-file`: each entry is one pill with the label ellipsized and the remove zone embedded at its end, sized by `--ful-controls-height` like every control, a danger wash on hover and the focus ring on the whole chip (an accent-fill-aware halo, the standard ring being invisible over the accent fill). The old detached square button after the row is gone; the remove button follows the quiet ghost idiom, a muted icon square whose danger appears on intent. A `multiple` select carrying `itemlist` hides its in-control badges (they stay in the dom, lifting the claim brings them back) and the open dropdown marks the options already picked (`picked`: an accent tint and bar, distinct from the walking cursor), the marking surviving reopen and re-search
- [ENH] the item lists are templatable: a `<template slot="items">` shapes each entry over the same `entries` overlay the stock chip renders from (`data-tpl-each="entries"`, `data-tpl-var="entry"`, each entry a `{ key, label, metadata }` object), the remove button's wiring unchanged
- [ENH] a claim landing while the dropdown is open drops the pick and closes the list
- [BUG] the remote loader shares one in-flight fetch across concurrent prefetch, search and lookups; a fetch superseded by a reconfigured url is discarded instead of stored for it; a cache write onto a full quota no longer fails the load that already succeeded, and a tampered entry under a cache key is a miss instead of a crash

#### ful-filter-*

- [REF] the operator, case-sensitivity and boolean-value menus are one `ChoiceButton`: an invoker button paired with the `ul[popover][role=menu]` that follows it, owning the fill, the whitelist, the pin-when-single rule, the popover wiring, the roving focus and the Escape/Enter handling, and calling back only when a pick changes the value. Three copies of the menu-click handler, two of `_showOperator`, the per-menu wired flags and the seven free functions they were spread across are gone, and the filters are left mapping tuples to choices
- [ENH] `ful-filter-boolean`'s value button carries `aria-haspopup` and an `aria-expanded` that starts at `false`, like every other menu invoker, instead of acquiring the latter only after its first open
- [ENH] the filters match the optionfactory data-jpa filter contract in full: `ful-filter-text` offers every `TextCompare` operator (`EQ NEQ LT GT LTE GTE BETWEEN CONTAINS STARTS_WITH ENDS_WITH`), the new `ful-filter-number` and `ful-filter-boolean` cover `NumberCompare` (`EQ NEQ LT GT LTE GTE BETWEEN` over numbers) and `BooleanCompare` (`EQ`/`NEQ` with the true/false tokens), and a `multiple` `ful-select` used as a filter emits the bare value array the `InEnum`/`InList` annotations expect. `CompareFilter`, the base of every compare filter, is exported from the ful entry
- [ENH] every filter whitelists its operators through the `operators` attribute, a comma separated list out of the filter's vocabulary (mirroring the annotations' `operators()`), and `ful-filter-text` whitelists its case sensitivity modes through `sensitivities` (mirroring `caseSensitivity()`). A single whitelisted entry pins the control: the glyph stays, documenting the choice, the popup goes and every emitted tuple carries the pinned value. Both are observed: changing them after rendering rebuilds the menu, re-normalizes the selection and re-arms or freezes the control; a pin lifted after the menu was wired re-links the invoker instead of leaving a dead button announcing a popup. The menus are generated from one shared table instead of three hand written copies, and the text filter gains a case sensitivity menu of its own (`aa`/`Aa`)
- [ENH] the operator menus are native popovers (`popovertarget` and CSS anchor positioning, light dismiss and Escape from the platform) and keyboard reachable: the menu opens on the operator in force, `ArrowUp`/`ArrowDown`/`Home`/`End` move with wraparound, `Enter`/`Space` pick and return the focus to the button, `Escape` returns to the button while the platform closes the popover, and a mouse pick restores the invoker's focus. The items carry `role="menuitem"` under a `role="menu"` with `tabindex="-1"`, the button staying the tab stop; `ful-filter-boolean` picks its value from the same popover menus, a select-looking button opening a localized `Any / ✓ Yes / ✗ No` menu in place of the native `<select>` it was prototyped with
- [ENH] the menus pair each glyph with its localized word (`= Equals`, `≤ At least`) in all four languages while the buttons keep the compact glyph; the ordered comparisons read as `< > ≤ ≥`, the text operators use continuation triangles (`a▸` starts, `◂a` ends, `◂a▸` contains). Both the operator and the case sensitivity buttons announce their current meaning through a localized `aria-label`, and each carries a minimum width so the filter row never jiggles when the operator changes; the operator button carries a subtle accent wash on `:focus-visible`, the control group's ring saying the filter has the focus and the wash saying the button specifically
- [BUG] disabled and readonly filters reach their chrome, not just their operands: the operator and sensitivity buttons carry the disabled claim (composed with a pin), a readonly filter inerts its control group so the popovers cannot open nor change anything, and the disabled buttons dim like every other disabled control
- [ENH] the filter operands moved inside a `ful-control` (the select's own shape) so they no longer share the bare-input family's chrome, and the filter chrome anchors on the structure (a `ful-affix` carrying the `operator`/`sensitivity` buttons), so custom filters built on the same pieces are styled without being on any tag list; the switch variant's transition yields to `prefers-reduced-motion`

#### ful-table and pagination

- [BRK] `ful-pagination.update({ current, total })` moves the pager to a page, a count, or both, and repaints once; it replaces the positional `update(current, total)`, which rendered without storing either or reflecting the attributes, so a caller could not use it without desynchronising the properties. `current` and `total` are one state: writing them one at a time repainted the bar twice per load, the first pass drawing the new page against the old count, which is what `ful-table` did on every load and now does in one call
- [DOC] `inHeaders` and `inRows` are named where the schema copies a column's attributes onto both cells: they are how an author writes a `data-tpl-*` that applies to the header or the body alone (`data-tpl-if="inRows"`), and both templates have carried the pair all along with nothing saying so
- [BRK] the table's initial message renders through `{{ }}` like every other built-in string, where it was the library's one `{{{ }}}`. No message ful ships is html-privileged now, so a consumer overriding `table.initial` gets text: a translation set fetched at runtime, which the README suggests, could otherwise have carried markup into the page through that one key. A test pins it by overriding the message with markup and asserting it never becomes an element
- [BRK] `page-requested` and `sort-requested` are `page:requested` and `sort:requested`, joining the colon-namespaced request families (`submit:*`, `section:requested*`) the rest of the library uses for an awaited round trip
- [BUG] the default in-memory table loader sorts: the schema renders a sorter for every sortable column whatever the loader is, and activating one over local data used to reorder nothing. Rows missing the sorted value sort last whichever way the column points
- [ENH] `ful-table` accepts a `response-mapper` component like `ful-select` and `ful-form` do, so a remote table can shape a payload that does not already match `{ data, size }`
- [BUG] each load is claimed: a response resolving after a newer load has started is stale, and neither renders nor updates the request a later `reload()` replays, whichever order the responses arrive in. A superseded failure is discarded the same way (no error state, no rejection) while the failure of the current load still renders and rejects; the header follows the load that owns it, so a sort resolving after a newer load started no longer wipes the winner's arrows. Previously two overlapping loads (a slow page request racing a sort or a filter) rendered in completion order and desynced every later reload
- [BUG] a response for a page the shrinking data left behind falls back to the last page that still exists; an empty table paginates as one empty page (`Page 1 of 1`, arrows dead, reload alive) instead of a phantom page one of zero; an `order` declared without its `sorter` asks the backend for nothing
- [ENH] the pagination controls are real `<button type="button">` elements instead of `a[role=button]` anchors: keyboard activation, disabled state and tab order come from the platform, the focus ring follows the theme, and a disabled page is no longer a tab stop; the reload button carries a localized accessible name, which the axe audit found missing
- [ENH] `ful-sorter` is focusable (`role="button"`, `tabindex="0"`), sorts on `Enter`/`Space`, carries the theme's focus ring and mirrors its order onto the header cell's `aria-sort` (`ascending`/`descending`, absent when unsorted)
- [BRK] the tables anchor their chrome on the `ful-table-wrapper` style-only tag and the pagination on `ful-pagination-bar` (a `role="navigation"` style-only tag standing in for the bare nav, so generic markup cannot catch the chrome); `.pagination`/`.page-item`/`.page-link` are plain `ul`/`li` with `data-ref` discriminators, disabled page links carry a `disabled` attribute instead of a class, and `.table`/`.alert` and the spacing utilities are replaced by structural styles under `ful-table`

#### ful: disclosures (tooltip, dialog, drawer, toasts)

- [BUG] `ful-drawer` opens on the side it was asked for: the default and `placement="end"` used to land against the inline **start** edge, the opposite one, in all three engines. The rule set `inset-inline-end: 0` and left the ua sheet's `inset-inline-start: 0` standing, which over-constrains a box with a definite width, and the start inset is the one that wins; `placement="start"` worked only because it set `inset-inline-end: auto` explicitly. The base rule now sets the symmetric `inset-inline-start: auto`
- [BUG] `ful-drawer` shows its dialog through one private method instead of a flag: `update()` used to set an instance field so that the `open()` it called two lines later would skip the section request, and reset it in a `finally`. - [REF] `wireAnchoredPopover(invoker, popover, { prefix, invoke, expanded, stretch })` owns the whole invoker/popover relation it is named for: it mints the id, links `popovertarget`, pairs `anchor-name` with `position-anchor` and mirrors the popover's `toggle` onto the invoker's `aria-expanded`, where the tooltip, the select and the filter menus each spelled those eight statements out. The naming happens whether or not the platform carries anchor positioning, since it is what the stylesheet reads; only the hand placement stays a fallback. The static `--ful-select` and `--ful-filter-operator` names are gone from the stylesheets, where the inline names always shadowed them and the three filter buttons sharing one name would have mis-anchored the sensitivity menu onto the operator button had they ever applied
- [NEW] `ful-tooltip`, `ful-dialog` and `ful-drawer`, distilled from the bootstrap tooltip, modal and offcanvas wrappers two applications carried. `ful-tooltip` is a themed icon button and a native popover carrying the slotted explanation (`placement` picks the side, Escape and light dismiss from the platform, `aria-expanded` announcing the state). `ful-dialog` is a native `<dialog>` with a header, a body and buttons, where `open()`/`ask()` resolve with the `data-result` of the button that closed it (null on Escape) and a localized acknowledge button shows when none is slotted. `ful-drawer` is the same dialog platform styled as a side panel (`placement="end|start"`), its `update(title, callback)` opening in a loading state and showing either the delivered content (the promise resolving with the content section, so a form is wired through the return value) or the problems a rejecting callback carries. - [NEW] `ful-toasts`: a transient feedback region, one per page, where each `show()` (or a `show-toast` document event carrying the same detail) stacks a toast that retires on its own timer (`timeout` attribute, five seconds by default) or its dismiss button, so concurrent messages no longer cut each other short; `severity` picks the theme and the announcement (`info` default, `success`, `warning`, and `error` announced as an alert), and a `Failure` message shows its problems' reasons
- [ENH] the family holds the library's invariants: `update()` claims each opening (a superseded delivery is not painted, a superseded rejection still travels to its caller but owns no drawer); an `ask()` waiter on a dialog leaving the document while open is answered with null instead of hanging forever; the `show-toast` listener is wired once per document and forwards to every live region (a second region no longer doubles every toast, a removed one stops answering); the failure reading is one helper for the drawer, the toasts and the table feedback; the drawer slides in from the inline end side in every writing direction
- [ENH] the chrome matches the rendered structure instead of the host tags, so a subclass overriding the template keeps the look: the `ful-toast` style-only tag and whoever hosts the toasts as the region, the button before a `ful-note` (or its `.ful-tip` class) as the trigger, the `ful-note` tag (or `.ful-note`) as the anchored bubble, the `ful-dialog`/`ful-drawer` classes on the native dialog; the geometry and the scrim are themed through `--ful-dialog-width`, `--ful-drawer-width`, `--ful-toasts-max-width` and `--ful-backdrop-color`
- [ENH] the drawer is the whole screen on a phone: below 30rem of viewport it drops its floating-panel metrics (full width, square corners), the width token still overridable
- [BUG] the tooltip's note is anchored again: the wiring named the anchor but the note carried no anchor positioning at all, so the popover fell back to the platform's centered fixed spot at the top of the page. The note claims the anchor's area per its placement attribute (`position-area` bottom by default, top, right, left), the margins staying the gap on the anchor-facing side, and the tests assert the geometry instead of the wiring alone
