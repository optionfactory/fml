### version 9.0.0

#### Upgrading from 8.x

The breaking changes, each detailed in its area below:

**Styling and markup**

- ful no longer depends on bootstrap in any form (css, js, icon font): every style ships in `dist/ful.css`, themed through `--ful-*` custom properties. Pages that relied on bootstrap classes in the rendered markup, on `bootstrap.bundle.min.js` for the filter menus, or on the icon font must drop them; `ful-table`/`ful-pagination` icon config keys take icon names (`'search'`, `'chevron-left'`, `'chevron-right'`, `'arrow-clockwise'`) instead of icon-font class names
- the `--ful-inputs-*` theme variables are renamed `--ful-controls-*`, joined by `--ful-controls-height`
- the structural hooks are style-only tags (`ful-control-group`, `ful-affix`, `ful-control`, `ful-badge`, `ful-choice`, `ful-table-wrapper`, `ful-pagination-bar`, `ful-tablist`, `ful-accordion-group`, `ful-steps`, `ful-toast`, `ful-note`) and the chrome anchors on the rendered structure instead of the host tags: custom css written against `div.input-group`, `span.input-group-text`, `.form-label`, `.badges`, `.pagination`, `.page-item`, `.page-link`, `.table`, `.alert` or `.ful-select-input-container` must move to the new hooks
- `ful-spinner` is a style-only tag: the `Spinner` export and the `.ful-spinner-wrapper`/`.ful-spinner-icon` hooks are gone, a self-registering page drops its `defineElement('ful-spinner', …)` line, and `role="status"` is the author's to carry

**Fields and forms**

- the positional slots of every field are `before` and `after` only, rendered inside a `ful-affix`; `ibefore`/`iafter` and the raw unthemed passthroughs are gone, so content once slotted raw now carries the addon styling
- the `disabled`, `readonly`, `required` and `value` claims stay live after the render, observed on the `Field` base; writing properties before the render is not supported, an attribute written between upgrade and render lands in the observed snapshot
- `ful-form`'s attributes are configuration, read once at the upgrade: `action`, `method`, `loader`, `request-mapper`, `response-mapper`, `clear-invalid-on-change` and `scroll-on-error`. Rewriting one after the form upgrades no longer takes effect, and all seven now appear in the element reference and the IDE metadata, where the form previously documented none
- `ful-form` submits one exchange at a time: a submit while one is in flight is dropped before the values are extracted
- while a `ful-form` submits it carries `aria-busy`, and the submit and reset buttons it holds off carry `aria-disabled="true"` rather than the `disabled` property, so they keep the focus: page css selecting `:disabled` on those buttons selects `[aria-disabled="true"]` instead

**ful-select and ful-dropdown**

- `ful-select.entry` answers `{ key, label, metadata }` entries instead of the `[key, [label, ...metadata]]` tuples exposed since ful 4.x
- the `csvm` attribute mapper is gone and `ful-select` declares `value:csv`: the value attribute is a comma separated list of keys whether or not the select is `multiple`. Nothing changes for a multiple select. A single select's attribute is now split and trimmed, so a key carrying a comma or padding (`value="a,b"`, `value=" it "`) must be assigned through the property, which does not go through the mapper. An element of your own declaring `value:csvm` moves to `csv` or to a mapper of its own through `static mappers`
- every `ful-select` loader method (`prefetch`, `load`, `exact`, `update`) and every `response-mapper` component answers `{ key, label, metadata }` entries. The positional `[key, label, ...metadata]` tuple survives only as the wire format a server sends, which the default response mapper converts: a custom loader or a named `response-mapper` returning tuples must return entries, and `metadata` is one value rather than the positional tail
- `ful-dropdown` names its own listbox and reports its active option through an `activechange` event, so a page driving a dropdown directly reads the event instead of the attribute; `aria-selected` marks the options that are picked rather than the one that is highlighted, which is what a stylesheet keyed on it now matches
- `ful-select`'s change detail carries the keys as `value` with the labeled selection beside it as `entry`; a `preload` select paints its label, combobox and error region at once instead of holding its upgrade on the prefetch; `ful-dropdown` names its own listbox and announces its active option through an `activechange` event, and `aria-selected` marks the options that are picked rather than the one highlighted

**ful-input**

- `ful-input`'s `mask` is replaced by `keep` and `reject`: `mask="[^0-9]"` becomes `keep="[0-9]"`, or `reject="[^0-9]"` for the identical behaviour under an honest name
- `ful-input`'s `type`, `v-type`, `keep`, `reject`, `uppercase` and `trim` are configuration, read once at the upgrade rather than on every use, so rewriting one afterwards no longer takes effect

**ful-table and ful-pagination**

- `ful-pagination.update({ current, total })` replaces the positional `update(current, total)`, and the page being shown is marked `aria-current="page"` and stays enabled where it used to be disabled
- `ful-table` emits `page:requested` and `sort:requested`, joining the colon-namespaced request family; `page-requested` and `sort-requested` are gone
- `ful-table`'s `page-size` is observed, so it stays live: writing it reloads from the first page. `ful-pagination`'s `pages` is configuration, read once at the upgrade rather than on every load
- every multiword attribute in the library is spelled with a dash. `ful-input-file`'s `maxfiles`, `maxfilesize`, `maxtotalsize` and `itemlist` become `max-files`, `max-file-size`, `max-total-size` and `item-list`, and `ful-select`'s `itemlist` becomes `item-list`. Their properties are `maxFiles`, `maxFileSize`, `maxTotalSize` and `itemList`, and css keyed on `[itemlist]` selects `[item-list]`
- the multiword localization keys are spelled with a dash too: `table.nodata`, `files.dropzonelabel`, `files.unacceptablefiletype`, `files.maxfilesizeexceeded`, `files.maxtotalsizeexceeded` and `files.maxfilesexceeded` become `table.no-data`, `files.dropzone-label`, `files.unacceptable-file-type`, `files.max-file-size-exceeded`, `files.max-total-size-exceeded` and `files.max-files-exceeded`. A page overriding one of those through the plugin's `translations` renames its own key
- the `table.initial` message renders through `{{ }}` like every other built-in string: a consumer overriding it with markup now gets that markup as text

**Localization**

- localization is one flat translations overlay: the plugin takes `new ful.Plugin({ language, translations })`, `ftl.Localization` is a plain template module (`#l10n:t()`, `#l10n:date()`, `#l10n:number()`, `#l10n:bytes()`), and the `l10n` static of `ParsedElement` subclasses is gone
- the plugin's overlay publishes `l10n` and `locale` only; `language`, which carried the primary subtag, is gone and `locale` carries the full tag

**Templates and elements built on ftl**

- ftl: `data-tpl-text` and `data-tpl-html` are gone (`>{{ x }}<` and `>{{{ x }}}<` replace them), and only `text/html` scripts are parsed as slot markup: any other script type (modules, the `text/markdown` the wiki once suggested) slots as the plain node it is
- elements built on `ftl`: `render(c)` receives `{ slots }` alone and the base applies the declared attributes onto the properties as soon as it returns, in declaration order, so a render that read `c.observed` reads what it needs through `declared(name)` instead; `reflect(fn)` is gone and `reflectTo(name, value)` is the only way back to an observed attribute, marshalling through the mapper the attribute was declared with; an attribute name a subclass re-declares takes the subclass's position in that order, which is how a field states that its `value` lands after the attributes its value setter reads
- a custom element must not call `attachInternals()` or declare an `internals` member: `ParsedElement` attaches the internals for every element and exposes them as `internals`, and a second call throws while a redeclared field wipes the base's
- custom fields implement `_build(conf)` and return their pieces: `render`, `_adopt`, `_wireLabel` and `_wireA11y` belong to `Field` and are gone from the authoring surface, and `skipObservedSetup` with them. All three claims read the host attribute, announce on the element named by the `announces` piece, and a field with no usable native `readOnly` names a `freeze` piece whose gestures the base refuses. A field's change detail always carries its own `value`, and an empty field reports `null` rather than `undefined`
- `reflect(fn)` is gone: `reflectTo(name, value)` is the only way back to an observed attribute, and it marshals through the mapper the attribute was declared with, so a setter that encoded its own type (`toggleAttribute`, a hand-built `setAttribute`) hands over the value instead
- `registry.upgrades`, a live `Map` iterator, is replaced by `pending()`, `whenUpgraded(el)` and `settle(accept)`
- one evaluation scope: `Template.withContext`, `withContextFrom`, `withModules` and `withData` collapse into `withEvaluator(evaluator)`, `Registry.context()` becomes `evaluator()`, and `Template.evaluate(expression, mode, ...data)` becomes `evaluateExpression(expression, ...data)` or `evaluateTemplated(text, ...data)`
- a render failure carries one frame per nesting level instead of two, each naming its node rather than serializing it, so a page matching on `RenderError` message text reads `Error evaluating data-tpl-each="rows" in \`<ul>\`` where it read `Error rendering template` followed by the whole template

**httpc**

- httpc: an error response whose body violates the `failures+json`/`problem+json` contract, does not decode, or is unreadable is a `GENERIC_PROBLEM` carrying the served status (it used to be `"undefined failures"`, a non-array `problems`, or a `CONNECTION_PROBLEM` with status 0); `Base64.decode` and `Hex.decode` reject invalid input instead of returning garbage; the csrf interceptor sends the token to the page origin only
- httpc builds the request url instead of splicing it: a second `?` no longer truncates the query, a `#` no longer swallows the parameters that follow it, and a fragment survives the parameters a call adds. A caller that hand-assembled a query string around these behaviours gets the url it actually asked for
- httpc tells a failed connection from a failed call: `CONNECTION_PROBLEM` now means the transport refused to deliver, a throw from the chain's own code (an interceptor bug, most often) arrives as `UNEXPECTED_PROBLEM` carrying the original as its `cause`, and `exchange()` rejects with an `HttpClientError` where it used to let the platform's raw `TypeError` through. `HttpRequestBuilder.param` overrides a key already set instead of appending to it, so a multi valued parameter is passed in one call

**Everything else**

- `Timing.debounce(ms, fn, { immediate })` and `Timing.throttle(ms, fn, { leading, trailing })` take object options; the six `DEBOUNCE_*` and `THROTTLE_*` constants are gone, `{ leading: false }` and `{ trailing: false }` replacing the two throttle flags
- the package declares `sideEffects: false`: bundler consumers importing through the root entry drop the unused parts of the bundle, and the `window.ftl`/`window.httpc`/`window.ful` assignments of the module entry may be tree-shaken away for them. Script-tag and CDN users of `dist/fml.mjs` are unaffected, `import * as fml` keeps the namespaces explicit
- `ful-local-date` and `ful-instant` declare `locale` and `default` as configuration, read once at the upgrade; both were already read only during the render, so nothing observable changes

#### ftl: templates, expressions and the registry

- [NEW] `ParsedElement` attaches the element internals for every element and exposes them as `internals`, adding a `rendered` custom state when the render completes. The platform allows one `attachInternals()` per element and throws on a second, so a subclass must never call it: `Field` used to, and now takes the base's, which costs nothing since form association follows the element definition rather than whoever attached. A subclass must not redeclare `internals` either, a class field with no initializer assigning undefined after `super()` returns and wiping it

- [REF] a class's `static config`, the constants its templates read as `config.*`, is read with the rest of its declaration when the registry is configured and travels in its `BITS`. The base used to loop over a one-element list of static names and look the value up on `this.constructor` every time a template was asked for, which had ftl reaching for a name only ful uses, once per render rather than once per class. A page overriding the constants replaces the static before `configure()`, like every other definition-time choice (`ful.Tooltip.config = { icon: 'my-icon' }` ahead of the plugin's configure); a replacement made afterwards is not picked up, where mutating the object in place still is
- [ENH] asking an element for an attribute its class never declared says so, with `Select declares no attribute 'my-endpoint': declare it in static observed or static attributes, or read it with getAttribute`, where `unmarshal` used to die on the missing mapper with `Cannot read properties of undefined`. The message names the wall it is: content an element does not own, a custom loader's own configuration on a `ful-select` host being the case that matters, is read with `getAttribute` like any other markup, and `declared(name)` answers for the declared vocabulary alone
- [BRK] `reflectTo(name, value)` is the one place a property is projected back onto its observed attribute, and `reflect(fn)` is gone. Sixteen setters re-opened the guard and re-encoded the mapper by hand, using `toggleAttribute` for the presence attributes, `Attributes.set` for the numbers, and a `setAttribute` carrying the browser's normalization of `accept` rather than the marshalled value, while two call sites used the method that already existed. A setter now hands over its value and never knows how its type serializes
- [ENH] a reflection that would write what the attribute already carries writes nothing, so reflecting a value an attribute change just delivered ends there instead of travelling back through the observer, and the mute is the attribute being written rather than the whole element. Deleting `reflect(fn)` is what closes the hazard the instance-wide mute carried: an arbitrary block ran under it, so any observed attribute a component legitimately changed while inside was silently dropped. Two blocks were not reflections at all: `ful-sorter` wrote `aria-sort` onto its ancestor `th`, which the guard never covered anyway, and `ful-pagination` re-rendered its whole bar inside it
- [BRK] `render(c)` receives the slots alone and the base applies the declared state onto the properties as soon as it returns, in the order the registry composed the declarations. Every element used to be handed an `observed` bag, and every one of them did the same thing with it: assign each value to its own property. `Field` had the generic loop; `ful-tabs`, `ful-sort-button`, `ful-pagination`, `ful-wizard` and `ful-accordion` hand-rolled a subset of it, and `ful-checkbox` and `ful-radio-group` destructured a bag they never read. A render needing a declared value while it builds reads it through `declared(name)`. The defaults those call sites carried moved into the setters that should always have had them, so an absent `total` or `current` on `ful-pagination` is zero rather than the string `"null"` in the dom
- [NEW] `static attributes` is the configuration tier, beside `static observed`: read once through its mapper when the upgrade starts and answered unchanged for the element's life, where an observed attribute stays live, forwarding to its property. The registry already composed the list and gave it a mapper, but nothing read it, so configuration was raw `getAttribute` at render (or at every use) with nothing in the class saying which. `ful-tooltip`, `ful-dialog`, `ful-drawer`, `ful-toasts`, `ful-table`, `ful-sorter`, `ful-select`, `ful-dropdown`, `ful-radio-group` and `ful-checkbox` declare theirs, and `declared(name)` reads either tier
- [BRK] a name a subclass re-declares takes the subclass's position in the composed order, which is what lets a field state that its value lands after the attributes its value setter reads: `ful-input-file` re-declares `value` after its constraints, since assigning one validates the selection against them. It used to work because `Field` special-cased `value` last, a rule the base could not state without knowing ful's vocabulary
- [BRK] the `csvm` mapper is gone, and `ful-select` reads its `value` as a plain `csv`. It was a general-purpose extension point built for one attribute: it hardcoded the literal string `multiple` in ftl's mapper table, which is a ful convention sitting in the layer that knows nothing about ful, and its `marshal` half was never reached from any element, since no field reflects `value` (the attribute is the initial value, as on a native input). Both of that marshal's branches computed the same string in any case, `String(array)` being `array.join(',')`. The select's `value` setter already normalized a scalar, a list or `null` into keys and its getter already answered a scalar for a single select, so reading every value as a list changes nothing a multiple select does and costs a single select the ability to carry a comma or surrounding space in a key given through markup. The declaration comment claiming `multiple` had to be declared before `value` described a constraint that did not exist: the mapper read the markup attribute and the element read `declared('multiple')` in its build, both before any property was applied
- [BUG] `Nodes.waitParsed` watches every ancestor of the element, not only its parent. The predicate it waits on reads the whole ancestor chain: an element last among its siblings becomes parsed when an *ancestor* gains one, and a childList observer on the parent never sees that mutation, so the wait fell through to its DOMContentLoaded deadline instead of resolving during the parse. Formatted markup hid it, since the whitespace before a closing tag is a text node the parent does gain, so what degraded was whitespace-free markup, where every element waited for the whole document rather than for its own closing tag. One observer takes many targets and is disconnected at the first checkpoint past the element either way, so the cost is one `observe()` per level: measured at 1ms for a hundred fields six wrappers deep, and 37ms for two thousand twelve deep
- [REF] `Registry.declarationsOf(klass)` is the one composition of a class's attribute declarations. The chain was walked in three places, the registry, the manifest generator and the metadata parity test, with two different stop conditions and two of them reading only `observed`, so the IDE metadata documented none of the configuration tier: `ful-tooltip`, `ful-dialog`, `ful-drawer`, `ful-toasts`, `ful-table`, `ful-sorter` and `ful-dropdown` each documented zero attributes while carrying author-facing ones. The manifest now describes 106 attributes where it described 90
- [BRK] a render failure carries one frame per nesting level instead of two, and each frame names its node rather than serializing it: `RenderError`'s message reads `Error evaluating data-tpl-each="rows" in \`<ul>\``, naming the directive, its expression and the node's open tag, where it used to read `Error rendering template` followed by the whole template's markup. The chain is the path from the outermost nesting down to the offending expression, which is what the two-frames-per-level shape buried; the render-level wrap now passes a framed failure through instead of adding a second frame for the fragment containing it
- [ENH] the chain spends a budget: `RenderError.FRAMES` frames are kept, the innermost being the specific ones, and a deeper nesting drops the outer context and sets `truncated` so a report can say so. The node's markup is no longer cloned into every frame either: `RenderError.html` serializes it when asked and `RenderError.node` is the live node, where the constructor used to deep-clone twice per frame on the failure path
- [BRK] the evaluation scope, the modules plus the data stack, is one value instead of a pair threaded by hand: `ExpressionEvaluator` is that value, a `Template` is a fragment plus one, and a `Registry` holds one it replaces whenever a module or an overlay is defined. `Template.withContext`, `withContextFrom`, `withModules` and `withData` collapse into a single `withEvaluator(evaluator)`, the one way to rebind a compiled template to a registry's scope, and `Registry.context()` is gone in favour of `evaluator()`. The nine command handlers and the render loop take the scope instead of the positional pair, and `Template.fromHtml(html, modules, ...data)` keeps its signature
- [BRK] the templated-versus-expression mode stops travelling as an optional middle argument: `Template.evaluate(expression, mode, ...data)` becomes `evaluateExpression(expression, ...data)` and `evaluateTemplated(text, ...data)`, and `ExpressionEvaluator.evaluate(expression, mode)` is replaced by the same pair, which it already carried. The mode symbol stays inside `Expressions`, where the parser needs it for its start rule
- [ENH] an element resolves through the registry that defined it, not through whichever one a module imported: the definition carries its registry in `BITS`, `ParsedElement` gained `component(name)` and `_registry`, and `template()` reads its own registry's context. `ful-form`, `ful-select` and `ful-table` no longer import the singleton, and the three loader factories resolve `http-client`, the request and response mappers and the `loader` component through the element they are handed, so a `new Registry()` is a working host for the elements it defines
- [BRK] `registry.upgrades`, a live `Map` iterator, is replaced by three named methods: `pending()` answers a snapshot of the elements still queued, `whenUpgraded(el)` the pending upgrade of one of them, and `settle(accept)` the rejecting barrier `Rendering` is now a three-line facade over. The queue keeps one entry per element holding both signals, the never-rejecting readiness one and the rejecting upgrade, where two maps were kept in lockstep by hand behind two fixed-point loops
- [ENH] `ParsedElement.rendered` answers whether the render completed, the moment the properties went live: `ful-tabs`, `ful-wizard` and `ful-toasts` each kept a private flag for that fact and now read the base's
- [BRK] `data-tpl-text` and `data-tpl-html` are gone, text and html land through the interpolations alone: the interpolation is a child text node instead of replacing every child, which nothing relied on. `{{{ }}}` accepts any value the attribute form accepted (numbers and `toString`-ables stringified, `null` and `undefined` rendering nothing) and `{{{{ }}}}` with a non-Node reports `Expected a Node`
- [BRK] only `text/html` scripts are parsed as slot markup; a page using another type as a markup container moves to `text/html`, and no script source is ever innerHTML-ed again
- [NEW] `data-tpl-stat` names an iteration stat beside `data-tpl-each`'s item: `{ index, count, size, first, last, even, odd }`, grouped under the declared name so it can never collide with data (an item property sharing the name wins). The stat observes without changing consumption: the size is read where the collection already knows it, and an iterator or generator is never consumed to learn it, its `size` and `last` reading null
- [ENH] `data-tpl-each` iterates keyed collections as `{ key, value }` entries: a `Map` in its own order, a plain object in `Object.entries` order (`<li data-tpl-each="languages">{{ key }}: {{ value }}</li>`); every other iterable iterates as itself, and a non-plain non-iterable still fails loudly
- [ENH] `registry.ready()` is the awaitable form of `ftl:ready`: the same promise for every caller, resolving right after the event and immediately when that moment already passed. Importing the registry after the document's DOMContentLoaded no longer strands the waiters (in the window before load included, the wait racing the two events rather than guessing from `readyState`), and a last-in-document element no longer strands its upgrade on a listener that would never fire
- [BUG] expressions: identifiers sharing a keyword's prefix (`nullable`, `nullish`, `falseFlag`, `truex`) parse again, the identifier rule taking the whole word and classifying the exact keywords after it; a call on a missing value reports `Method missing` (by name where the grammar knows it, a bare `boom()` included) instead of crashing while building its own message; a template string is a valid dict key, evaluated like any other, where `{`{k}`: 1}` used to collapse into a literal `"undefined"` key
- [BUG] a lone `{` in a templated text node renders as itself: the parser's negative lookahead leaked into the joined parts, so a text carrying interpolations plus a single brace (`cost {{x}} is {high}`) rendered a stray comma
- [BUG] fireAsync: a pipeline or delegate configured wrong still throws its configuration error to the caller, but the outcomes of the listeners it already dispatched are owned instead of surfacing as unhandled rejections the page's error reporter would post

#### httpc, client-errors and storage

- [NEW] httpc exports every type its own signatures hand back: `HttpClientBuilder` (what `builder()` answers), `HttpRequestBuilder` (what all seven verbs answer), `HttpInterceptorChain` (what an interceptor is handed) and `HttpMultipartRequestCustomizer` (what a `multipart` callback is handed). They were reachable and unnameable, emitted into `httpc.d.mts` as non-exported `declare class`, so a consumer could write the call but not annotate the function it lives in, nor type the `chain` parameter of an interceptor of their own. The two built-in interceptors stay unexported: they are page policy the builder installs, not a type anything hands back
- [BRK] a connection problem is the connection failing, and nothing else: `HttpCall` labels its own rejected `fetch` as `CONNECTION_PROBLEM` below the chain, so a throw from the chain's own code, most often a bug in a consumer's interceptor, reaches the caller as `UNEXPECTED_PROBLEM` carrying the original as its `cause`. `fetch()` still answers a `Failure` whatever was thrown, so a caller reading `problems` never has to test the shape first; it is the label that stopped sending readers to look at the network for a `TypeError`. The reporter walks the cause chain, so the real stack now arrives in the report where it used to flatten to `unknown failure`
- [BRK] `exchange()` answers the same failure the request builders do when the transport refuses: the wrap moved below it, so a network failure is an `HttpClientError` there too rather than the platform's raw `TypeError`. The same fact reads the same way whichever call was made
- [REF] `HttpClientError.problem(type, reason)` mints the problems the client makes itself; the object was spelled out at four sites
- [BUG] client-errors reports the cause chain: it read `message` alone, and neither a message nor a stack carries `cause`, so every framed failure in the library arrived naming where it surfaced and never what caused it. The report now walks the chain to a bounded depth, joining the frames with `Caused by:` lines, stopping on a cycle, and noting when a chain dropped its outer frames
- [BRK] the request url is built instead of spliced: a second `?` no longer truncates the query and a `#` no longer swallows the parameters into the fragment where the server never sees them (the fragment is split off and reattached after the parameters, the query splits at its first `?` only); `param` skips nullish entries among real values in any position, like the plural forms always did
- [BRK] an error response reports faithfully whatever went wrong with its body as a `GENERIC_PROBLEM` carrying the served status: not decoding as json (a proxy's html error page carrying the wrong content type, a truncated response), decoding to json that violates the `failures+json`/`problem+json` contract, or unreadable altogether. Previously a served response was mislabeled as a network failure with status 0 and the status hidden behind a json parse error
- [BRK] `Base64.decode` and `Hex.decode` reject invalid input (characters outside the dialect, misplaced or overlong padding, impossible lengths, non-hex characters) instead of returning plausible-looking garbage
- [BRK] the csrf interceptor carries the token to the page origin only, so a cross-origin request no longer ships the session token to a third party; it reads the meta pair at request time, so metas landed after the client was built are honored without a rebuild
- [BUG] `HttpClient.exchange()` normalizes its options before the chain sees them, every interceptor receiving a `RequestInit` with a real `Headers` however bare the call. A bare `client.exchange(uri)` under a `CsrfTokenInterceptor` (the ful plugin registers one by default) used to crash on the missing headers field
- [ENH] `fetchJson()` yields `null` on a 204 instead of failing to decode the body the status declares absent
- [BUG] client-errors sends the csrf header only when the meta pair is complete (a half-configured page used to send a literal `"undefined"` token on every report), and its missing-attribute complaint is logged once per page, not once per captured failure
- [BUG] storage: an unreachable backing (blocked cookies, and the embedded or private contexts where the accessor itself throws) reads as a miss and removes as a no-op instead of failing the caller, so a revisioned `ful-select` still loads its options from the network there; writes keep reporting to their caller

#### Localization

- [BRK] the plugin's overlay publishes two names, not three: `l10n`, the messages a template resolves through `#l10n:t()`, and `locale`, the full tag every formatter needs. The `language` key carried the primary subtag, which exists to pick which built-in bundle is layered under a consumer's strings and is read by nothing once that is done: a bare, generic name occupying the scope of every template on the page for no reader. A page that wants it takes it from `locale`
- [BRK] localization is a single flat translations map instead of per-class dictionaries: `ftl.Localization` is a plain template module (`#l10n:t('pagination.showing', …)` with named `{placeholders}`, `{ one, other }` plural leaves selected through `Intl.PluralRules` over a numeric `{count}`, and `#l10n:date()`/`#l10n:number()`/`#l10n:bytes()` honoring the page locale), resolvable from any template or imperatively through `Localization.of()`. The messages live in per-language files under `src/ful/l10n/`, kept at parity across languages by a dedicated test; the `l10n` static of `ParsedElement` subclasses is gone
- [BRK] the ful plugin takes `new ful.Plugin({ language, translations })`: the language is fixed per page (a full BCP-47 tag or a primary subtag, defaulting to the browser's) and the fallback chain is baked once at configure into one `l10n` overlay; `translations` is a flat active-language map applied over the built-ins, rewording them or adding keys of your own, and a remote set is an awaited `fetch().json()` handed over before `configure()`
- [ENH] `ful-local-date` and `ful-instant` resolve their locale from their `locale` attribute, the page's locale, then the platform default; file size warnings carry locale-formatted digits (`1,5MiB` in Italian) through `#l10n:bytes()`, replacing the bespoke byte formatter

#### ful-filter-*

- [NEW] `ful-filter-in` takes an `operator`: a fixed token sent in front of the chosen keys, for the field a compare reads rather than a set. No menu is rendered either way, the operator being the author naming the server's comparison rather than a choice offered to whoever is filtering, which is what separates the singular attribute from the plural `operators` that narrows a menu on the compare filters. `criterion` reports it, so a chip shows it like any other. - [ENH] `ful-filter-in` filters on set membership, answering for both of the data-jpa set annotations: `InEnum` and `InList` take the same bare array of values and no operator at all, differing only in what the server converts them to, so one element covers both and the client never has to know which the endpoint declared. The value is an array either way, a set of one still being a set where a bare key is not what the filter request takes. - [REF] the operator, case-sensitivity and boolean-value menus are one `ChoiceButton`: an invoker button paired with the `ul[popover][role=menu]` that follows it, owning the fill, the whitelist, the pin-when-single rule, the popover wiring, the roving focus and the Escape/Enter handling, and calling back only when a pick changes the value. - [ENH] the filters match the optionfactory data-jpa filter contract in full: `ful-filter-text` offers every `TextCompare` operator (`EQ NEQ LT GT LTE GTE BETWEEN CONTAINS STARTS_WITH ENDS_WITH`), the new `ful-filter-number` and `ful-filter-boolean` cover `NumberCompare` (`EQ NEQ LT GT LTE GTE BETWEEN` over numbers) and `BooleanCompare` (`EQ`/`NEQ` with the true/false tokens), and the new `ful-filter-in` covers `InEnum` and `InList`. `CompareFilter`, the base of every compare filter, is exported from the ful entry
- [ENH] every filter whitelists its operators through the `operators` attribute, a comma separated list out of the filter's vocabulary (mirroring the annotations' `operators()`), and `ful-filter-text` whitelists its case sensitivity modes through `sensitivities` (mirroring `caseSensitivity()`). - [ENH] the menus pair each glyph with its localized word (`= Equals`, `≤ At least`) in all four languages while the buttons keep the compact glyph; the ordered comparisons read as `< > ≤ ≥`, the text operators use continuation triangles (`a▸` starts, `◂a` ends, `◂a▸` contains). - [BUG] a `ful-filter-*` rendered from a `value` attribute shows the operator it is actually using, and a `BETWEEN` range reveals the second bound it carries. Both used to keep the template defaults, so the control disagreed with its own value
- [BUG] `ful-filter-text` reports back the sensitivity it was given instead of always reporting `IGNORE_CASE`, which silently downgraded a `CASE_SENSITIVE` query
- [ENH] `ful-filter-*` emits `change` when the second bound of a range is edited or a new operator is picked, not only when the first bound changes
- [BUG] `ful-input-file` shows one warning per violated constraint instead of only the last one, and clears them as soon as a later selection is clean
- [BUG] `ful-input-file` keeps its selection when a drop carries no file, so dragging text or a link over the dropzone no longer wipes the picked files
- [BUG] `ful-input-file` enforces its constraints and refreshes its item list when `files` or `file` is assigned programmatically, not only when the user picks or drops
- [BUG] `ful-input-file` removes only the clicked item when two selected files share a name
- [REF] the `unaccepptablefiletype` localization key is spelled `unacceptablefiletype`
- [BUG] the `mask` of a `ful-input` no longer throws on the input types that have no caret, `email`, `number` and the date ones: the value is masked and only the caret restore is skipped
